# FIX D-09 — admin engineering grant leaves no audit row

**Class:** FIX (accepted change 1/5). **Severity:** S2. **LOC:** +36 / −5 across 4 files (prod: 3 files, +30).

## Defect (live, [MEASURED])

`evidence/stage2/s17_admin_ab_transcript.log`:

```
B POST /v1/admin/engineering/grants {"tenant_id":"<dev>","permissions":["workspace.exec"]} -> 200
audit rows for grant in B view: 1 ['login']      # unchanged
```

An admin added WRITE permissions to another tenant's firewall policy and no audit
row was produced anywhere. `AuditEventType.SECURITY_POLICY_CHANGED` (20 §9 must-audit)
had zero emitters (`grep -rn SECURITY_POLICY_CHANGED apps core --include=*.py` → contracts
enum + notifications filter only). `EngineeringAdminSurface` had no audit port.

## Change

- `apps/api/engineering_admin.py`: `EngineeringAdminSurface.audit: AuditLogPort | None = None`;
  `grant(body, *, actor_id, actor_tenant_id)` appends one `SECURITY_POLICY_CHANGED` row under the
  **target** tenant with `details={surface: engineering_grant, actor_tenant_id, permissions,
  granted_permissions, outcome: granted}`. Refused grants (`ValueError`) raise before the append —
  no row is written for a mutation that did not happen.
- `apps/api/admin.py`: route passes `admitted.user_id` / `admitted.tenant_id`.
- `apps/composition/runtime.py`: binds the same `audit` instance the rest of the platform uses.
- `tests/engineering/test_admin_seam_and_composition.py`: helper binds `world.audit` (existing tests unchanged).

No new abstraction, no new endpoint, no behaviour change on the response body.
