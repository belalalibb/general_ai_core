## Method (differs from the R172 probe — recorded as a finding)
- Harness: tests_live/r173/test_live_probe.py (new dir tests_live/r173/, outside `testpaths`;
  never collected by the hermetic verifier; skips cleanly when no GROQ_API_KEY_* is exported).
- Path exercised: build_runtime_profile(environ={GROQ_API_KEY, DEV_DEMO_PRINCIPAL=1,
  PROVIDER_MAX_RETRIES=0}) -> create_app -> POST /v1/execute
  {"ask": "Reply with exactly the word: OK", "model_policy": {"type": "auto", "allow_fallback": false}}.
  The router (not the probe) selected the model; the composition's own GroqAdapter carried the request.
  The R172 probe called the adapter with a hand-picked non-manifest model and bypassed the router —
  R173 fixes this so the proof is of the platform, not of the adapter alone.
- Provider-level truth (provider_code, retry_after_ms) is not exposed on the HTTP envelope
  (only provider_error_category is). The probe therefore wraps the adapter object inside
  profile.adapters (the same dict ExecutionService reads) with a pass-through observer.
- Bounded attempts: PROVIDER_MAX_RETRIES=0 and allow_fallback=false -> exactly one provider call per key,
  except one deliberate retry if the first attempt's category is "timeout".
- Recorder: every record() call is asserted against EVERY present secret-shaped env value
  (names matching KEY|TOKEN|SECRET|PASSWORD, value length >= 12) and against the prefix regexes
  gsk_/ghp_/github_pat_. This closes the R172 blind spot where only GROQ names were checked.
